# sim-nav-map 能力信封（Capability Envelope）

2026-07-02 与用户逐条拍板。**用途：约束游戏设计** —— 设计默认在信封内进行；
突破信封 = 显式的底座变更讨论，不是隐式假设。底座按信封做硬化与性能承诺，
硬化完成前信封不扩容。

## 支持的能力

| # | 能力 | 拍板 | 说明 |
|---|---|---|---|
| 1 | 地图尺寸 | ✅ ≤ 512×512 格 | 表内存 ~4MB/通行类；增量修复成本不随图涨 |
| 2 | 技能造墙 / 砍树 | ✅ 支持 | 格子对齐障碍、出现/消失是事件；走 dirty → 增量修复链路 |
| 3 | 会移动的墙 | ❌ 不支持 | 连续移动的障碍 = 每帧重建；需要时当"不可推单位"走分离求解，不进导航图 |
| 4 | 高低地 / 多地形 | ✅ 支持 | 走通行 flag（既有机制）；高地视野/miss 不属于导航底座 |
| 5 | 单位规模 | ✅ ≤ 100 同屏移动 | 触发分离求解空间哈希刀（硬化清单 ③） |
| 6 | 通行类型 | ✅ 少数几类（地面/飞行…） | 每类一套表；飞行近似直线走，几乎免费 |
| 7 | 单位互挡 | ✅ 单位不进导航图 | 挤开/贴身绕行/creep block = 分离求解（已验收手感）；❌ 不做单位占格式寻路 |
| 8 | 命令目标形状 | ✅ 点（快路径）+ 圆 | 方形等保留可用但不承诺性能 |
| 9 | 真编队（阵型锁定） | ❌ 暂不支持 | 现有散点 fanout 够用；真编队是独立机制，撞墙再谈 |

## 性能承诺（硬化完成后固化为 budget smoke，跌破即测试红）

- 单条跨图长径规划 < 1 ms（当前实测 ~0.8 ms @ 165×113）
- 造墙一次表修复 < 2 ms（当前实测 ~0.7 ms；⚠ 完整 flush 链路当前 ~30 ms，
  大头是 hierarchical 单 chunk 重算 ~29 ms —— 硬化清单 ⓪ 的对象）
- 100 单位移动 tick < 5 ms（依赖清单 ②③）
- 规划预算每 tick 1-4 条可调（`PLAN_BUDGET_PER_TICK`）

## 硬化清单（黏土内完成，按序）

| 序 | 刀 | 状态 |
|---|---|---|
| ① | 路牌表（jump ray tables）增量修复 + "增量==全量"等式 smoke | ✅ 2026-07-02（修复 ~0.7 ms，`smoke_sim_nav_jump_table_repair`）|
| ⓪ | hierarchical 分区连通性重算增量化（造墙 flush 的真大头，单 chunk ~29 ms）| ⏳ 造墙技能落地前必修 |
| ② | `is_line_walkable` 视线检查查表化（逃逸规则孪生 + 保留形状段 + 独立 A/B）| ⏳ 单位 30+ 触发 |
| ③ | 分离求解空间哈希（O(N²) → 近线性）| ⏳ 单位 50+ 触发 |
| ④ | budget smoke 套件（把上面的承诺焊进测试）| ⏳ ②③ 后 |
| ⑤ | GDExtension 铸模（含分离求解；Web/WASM 构建链）| ⏳ 信封冻结 + ⓪-④ 完成后 |
