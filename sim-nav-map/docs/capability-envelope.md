# sim-nav-map 能力信封（Capability Envelope）

2026-07-02 与用户逐条拍板。**用途：约束游戏设计** —— 设计默认在信封内进行；
突破信封 = 显式的底座变更讨论，不是隐式假设。底座按信封做硬化与性能承诺，
硬化完成前信封不扩容。

## 支持的能力

| # | 能力 | 拍板 | 说明 |
|---|---|---|---|
| 1 | 地图尺寸 | ✅ ≤ 512×512 格 | 表内存 ~4MB/通行类；增量修复成本不随图涨 |
| 2 | **地形动态改变**（运行时通行性变更） | ✅ 支持 | 一个抽象、一条链路：技能造墙、砍树、开门、塔亡让位……全是"改格子 → dirty → 增量修复 → 重规划"的实例。约束：格子对齐、出现/消失是**事件**（非每帧连续） |
| 3 | 连续移动的地形（会走的墙、推着走的障碍） | ❌ 不支持 | 即 #2 的"每帧连续版" = 每帧重建；需要时当"不可推单位"走分离求解，不进导航图 |
| 4 | 高低地 / 多地形 | ✅ 支持 | 走通行 flag（既有机制）；高地视野/miss 不属于导航底座 |
| 5 | 单位规模 | ✅ ≤ 100 同屏移动 | 触发分离求解空间哈希刀（硬化清单 ③） |
| 6 | 通行类型 | ✅ 少数几类（地面/飞行…） | 每类一套表；飞行近似直线走，几乎免费 |
| 7 | 单位互挡 | ✅ 单位不进导航图 | 挤开/贴身绕行/creep block = 分离求解（已验收手感）；❌ 不做单位占格式寻路 |
| 8 | 命令目标形状 | ✅ 点（快路径）+ 圆 | 方形等保留可用但不承诺性能 |
| 9 | 真编队（阵型锁定） | ❌ 暂不支持 | 现有散点 fanout 够用；真编队是独立机制，撞墙再谈 |

## 性能承诺（硬化完成后固化为 budget smoke，跌破即测试红）

- 单条跨图长径规划 < 1 ms（当前实测 ~0.8 ms @ 165×113）
- 一次地形动态改变的**完整 flush** < 5 ms（当前实测 ~3.5 ms = 表修复 ~0.7 +
  hierarchical 窗口化重算 ~2.5 + 杂项；曾为 ~30 ms）
- 100 单位移动 tick < 5 ms（依赖清单 ②③）
- 规划预算每 tick 1-4 条可调（`PLAN_BUDGET_PER_TICK`）
