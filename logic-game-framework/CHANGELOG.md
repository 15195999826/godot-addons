# Changelog

本文件记录 Logic Game Framework 的重要变更。格式参考 [Keep a Changelog](https://keepachangelog.com/)。

- **Added** — 新增能力
- **Changed** — 行为或 API 变化
- **Fixed** — Bug 修复
- **Removed** — 移除
- **Deprecated** — 即将废弃

新变更追加到 `[Unreleased]` 段下，按上述分类组织；每条写清 **API 变化** 与 **why**。架构级取舍写进 `docs/README.md`（设计铁律 / 架构节）或 `docs/reference/`，不另开逐阶段长文。

## [Unreleased]

### Added
- **context 存活计数 `ExecutionContext.get_live_count()` / `AbilityLifecycleContext.get_live_count()`**：`_init` 加一、`NOTIFICATION_PREDELETE` 减一，所有构建都计。释放测试每个用例断言计数回到用例开始前，hex `smoke_skill_scenarios` 与 inkmon `smoke_m1_battle` 收尾断言归零。why：context 携带 instance 强引用、只许活在调用栈上，而 weakref 探针只挂在四条构造路径上——on_remove / 叠层 / Break 钩子、cancel、`can_activate`、PreEvent 重建、callback context 任一把 context 存进字段，三关照样全绿；计数是覆盖全部构造点的机制级兜底。不按 `OS.is_debug_build()` 门控：引擎每次释放都向脚本 `_notification` 分派 PREDELETE 与 PREDELETE_CLEANUP 两次、与构建类型无关，门控省不掉分派，只会多一次调用，并让 release 下的归零断言恒真。
- **`EventProcessor.set_trace_level(level)`**：运行期切换本 processor 的 trace 级别（0 不记 / 1 基础 / 2 详细）。递归深度超限报错的「事件调用链」提示改为指向它：重跑前对所属 instance 调 `event_processor.set_trace_level(1)`。why：`EventProcessorConfig` 改随 instance 构造之后，hex / dota2 / skill-preview / harness 的世界 `_init` 都不收 config，原提示「重跑时传 `EventProcessorConfig.new(max_depth, 1)`」对它们无从下手。
- **`AbilitySet.get_owner_instance() -> GameplayInstance`、`AbilityLifecycleContext.instance`、项目级 `world(ctx)` helper**：context 携带所属 instance（见 Changed「typed instance」）。hex `HexBattleGameStateUtils.world`——`as` 收窄 + 类型不符（含 null）时 `Log.assert_crash`；原本拿到就解引用、不判空的 6 处读点（移动 ×2 / 推击 / 反伤 / 伤害 / 治疗）改走它。原本就判空降级的读点保留 `var battle: X = ctx.instance` 再判空、语义不变——inkmon / dota2 的读点全属此类，暂不需要 helper（出现第一处必须有世界的读点时照 hex 加一个）。测试：新增 `tests/core/abilities/instance_context_test.gd`（6 用例：派发的 trigger filter 与 NoInstance action、`can_activate` 查询的 Condition、lifecycle 的 on_apply / on_remove、execution 的 start / tag / revoke 触发的 cancel、PreEvent 重建的 context 都拿到 owner 所属 instance；owner 未注册给 null，且 GRANTED_SELF 照样自激活；随后 P4 加第 7 个：未注册 owner 拿不到事件设施时的降级，见 Changed「事件设施归 GameplayInstance」）；释放测试在 NoInstance on_apply action、trigger filter、事件 action、timeline tag action 各挂 context 探针，grant / tick / 派发一返回即断言 context 已释放。
- **`BattleActor`（`core/entity/battle_actor.gd`）**：core 承认「带 AbilitySet 的 actor」是一等公民。`Actor` 保持中性，`BattleActor` 是 opt-in 的死亡锁存与战斗骨架——`check_death`（首次归零返回一次 true）/ `mark_dead` / `is_dead` / `is_pre_event_responsive`、`_on_id_assigned` 把 id 同步进 ability_set + attribute_set、录像默认实现（`get_attribute_snapshot` 全属性 / `get_ability_snapshot` / `get_tag_snapshot` / `setup_recording` 三条订阅）、`serialize()`（base + 属性 raw + `is_dead`，位置留项目层）、以及 `team_id` 与 `set_team_id` / `get_team_id`。**基类不声明 `ability_set` / `attribute_set` 字段**，走虚函数 `get_ability_set() -> AbilitySet` / `get_attribute_set() -> BaseGeneratedAttributeSet`（默认 null，子类协变返回收窄），专属代码仍可 `actor.attribute_set.atk` 直访而不被基类 shadow。所有方法对 null set 走**真实分支**而非断言（`Log.assert_crash` 在 debug 下只中止自己那一帧，挡不住半成品对象继续被用）；`has_hp()` 把「没血条」与「血条为 0」分开，纯数据 actor（overworld 玩家 / NPC）不会被 `check_death` 判成尸体。血条读法两级可覆盖：换容器覆盖 `_hp_source()`，换属性名覆盖 `has_hp()` + `get_current_hp()`（`check_death()` 只经这两个虚函数取值）。`set_death_latch(value)` 是唯一能把死亡闩拨回 false 的入口——「从 HP 复活」是项目规则，core 不定义它，但也不该逼项目层去写基类私有字段。附 `static func ability_set_of(actor: Actor) -> AbilitySet`。测试 `tests/core/entity/battle_actor_test.gd`（13 用例）。why：三个消费者各自抄了一份同形骨架（hex `HexBattleActor` / dota2 `Dota2BattleActor` / inkmon `InkMonBattleActor`），core 却只能靠 `"ability_set" in actor` 鸭子摸字段——真类型一进来，三份副本合一、core 的字符串探测清零。
- **`AbilitySet.tick_runtime(dt, logic_time, provider) -> bool`（provider 尾参随后由同段 Changed「typed instance」删除） + `has_executing_instances()` + 虚钩子 `_is_blocking_execution(ability) -> bool`（默认 true）**：回合 / ATB 主循环里一帧 ability runtime 的唯一形状——`tick` → 算 blocking → `tick_executions`，返回本帧是否有阻塞执行（实时 tick 的 dota2 不走它，自行编排相位）。blocking **必须在 `tick_executions` 之前**算：本帧内跑完的 execution 也占这一帧，先推进再问会让角色在收招那帧既施法又充能。项目子类覆盖钩子表达自己的「常驻能力不冻结行动」规则（hex `BattleAbilitySet` 与 inkmon `InkMonBattleAbilitySet` 均为 `not ability.has_ability_tag("intrinsic")`）。配套新增不分配中间数组的 `Ability.has_executing_instance() -> bool`（`get_executing_instances()` 每次调用都 `filter` 出一个新 Array，而主循环每 actor 每 tick 只想知道有没有）。why：这套顺序此前是 hex 与 inkmon 两份逐字相同的 procedure 静态三件套，顺序不变量只活在注释里。
- **`GameWorld.get_instance_of_actor(actor_id) -> GameplayInstance`**：由 actor id 直接反查所属实例（与 `Actor.get_owner_gameplay_instance()` 同一「id 自描述归属」机制，但不需要先拿到 Actor）。`get_actor()` 改为走它，`{instance_id}:{local_id}` 的解析从此只有一处。
- **`RawAttributeSet.snapshot_current_values() -> Dictionary`**（原私有 `_snapshot_all_values`）：全属性当前值快照。why：`BattleActor.get_attribute_snapshot()` 需要同一份定义，快照语义（跳过谁、怎么取值）不能有两套。

- **`AbilityConfig.lint_timelines(configs) -> Array[String]`**：校验一批 config 携带的 timeline——合法性（`validate()`）、tags 已冻结、同 id 必须同实例，返回人类可读问题列表。why：`TimelineRegistry` 退役后「同 id 异实例」失去运行时守卫（id 只剩录像标签用途，两份节奏顶同一个 id 会让回放 `timelineId` 静默串味），静态检查接管；放 core 而非 example 是因为三个消费者各有 manifest，守卫不能只长在 hex 一家（hex `smoke_manifest_lint` 断言① 与主游戏新增的 `inkmon/tests/smoke_skill_manifest_lint` 都调它）。
- **释放测试 `tests/core/world/refcount_release_test.gd`（登记 `run_tests.gd`）**：对 instance / actor / ability_set / tag_container / attribute_set / ability / 每个 component / execution instance / EventProcessor / EventCollector 逐个取 weakref，`destroy_instance` 后断言全部归 null；第二用例走 `start_battle` + 录像，覆盖 BattleProcedure / BattleRecorder / RecordingContext / 订阅闭包，`battle_finished` 后同样全部释放。why：GDScript RefCounted 无循环 GC，引用环只能靠机器守——后续每引入新的持引用对象都往这里加 weakref（LGF core 重构计划 D12 硬关卡）。
- **Ability 激活门纯查询 `can_activate`（`AbilitySet` / `Ability` / `ActiveUseComponent` 三级同名 API）**：零副作用干跑任意 ActiveUse 激活门——不扣资源、不 push `AbilityActivateFailed`、不创建 execution、可重入；按激活路径同序评估全部 `Condition.check` → 全部 `Cost.can_pay`，并镜像 `receive_event` 的顶层短路（未 granted / disabled 同判拒绝）。返回结构化 Dictionary `{allowed, reason, failed_component_type}`，键与取值常量收口在新类 `AbilityActivationQuery`（`core/abilities/shared/ability_activation_query.gd`）；`reason` 与激活失败事件同源（`get_fail_reason`），`failed_component_type` 与 `GameEvent.AbilityActivateFailed` 同词汇（"condition"/"cost"，真实路径的字面量同步改引同一常量源，另有 ability 级 "ability"）。有意不含 trigger 匹配——trigger 表达"何时把事件派给组件"，cast 前查询没有事件可匹配；`event_dict` 仅作透传给 check/can_pay 的拟真输入。why：UI / AI / tooltip 三源合法性 Query 此前拿不到 Condition/Cost 这份运行时门控真相——要么带副作用地 dry-run cast 流程，要么在业务层复刻冷却/资源规则形成双源漂移；cast 前过滤的 metadata 声明式路径不变（见 CLAUDE.md 配置归属表），本 API 只补"已配置门控的无副作用复核"这一缺口。测试 `tests/core/abilities/active_use_query_test.gd`（6 用例：零副作用/可重入、condition/cost 结构化拒绝、查询不 push 失败事件（对照真实路径 push）、disabled/expired 同判、查询不预扣真实支付、多组件首败返回）。

- **`AbilitySet.grant_ability(ability)` 恒投递 `AbilityGranted`（breaking）**：删 provider 参数。此前「传不传 provider」兼任「要不要投递」开关——hex 的移动 / 职业技能 / 职业被动 / 振奋 buff / 装备 passive、dota2 基础攻击、inkmon 装备通用 ability 都靠不传来静默；现在是否自激活只由 ability 自己声明的 trigger（`TriggerConfig.GRANTED_SELF`）决定，与调用点无关。逐个核对过这些今日静默的调用点：它们 grant 的 ability 都不声明 `abilityGranted` trigger，投递无观察者——`hex/skills` 全部 scenario 与 inkmon `smoke_battle_golden` 指纹不变，未启用 `grant_ability(ability, broadcast_granted)` 退路。投递不写录像（录像里的 `AbilityGranted` 仍由 `on_ability_granted` 订阅产生）。why：一个参数同时表达「世界是谁」与「要不要通知」，去掉前者时后者必须显式化；交给 config 声明后，装备容器也不必为了 self-trigger 去存 owner instance。
- **timeline 直传（breaking）**：`ActivateInstanceConfig` / `ActiveUseConfig` 删 `timeline_id` 字段，构造首参改 `timeline: TimelineData`（尾参 `timeline_data` 删除）；builder `.timeline(data)` 声明即 `tags.make_read_only()`（幂等），`build()` 断言 timeline 非空；`Ability.activate_new_execution_instance(p_timeline: TimelineData, …)` 与 `AbilityExecutionInstance._init(p_timeline: TimelineData, …)` 直传引用（公开 `timeline_id` 保留，但从可写 String 字段变为只读派生属性 `get: return _timeline.id`——录像 / 事件侧读它，类内自己读 `_timeline.id`）。行为变化：缺 timeline 从「警告 + 立即完成 / error 拒绝激活」这种静默降级，变成声明期就炸响（debug 下 `assert` 打 SCRIPT ERROR 并中止该帧，release 下 `OS.crash`）；tags 冻结时机从战斗开始（注册）提前到声明时；`AbilityActivationQuery` 不再有 timeline 缺失分支。why：`.timeline(data)` 一体化后 config 树已握有引用，registry 只剩「声明 → 注册 → 按 id 查回同一引用」的空转，漏注册是运行时才炸的静默失效面；删掉后漏 timeline = build 期 crash。

### Fixed
- **world 结束时进行中的战斗泄漏 recorder 与全部被录 actor；直接 `finish()` 后战斗槽位陈旧**：`WorldGameplayInstance.end()`（覆盖基类，先于 `super.end()` 的 despawn）对仍在进行的战斗调新增的 `BattleProcedure.abort()`——断开 `actor_added`、新增的 `BattleRecorder.abort_recording()` 退订全部订阅闭包且不产出录像、标记结束；不发 `battle_finished`、不清 `in_combat`、不经子类 `finish()`（不存日志 / 不写回放 / 不改任务状态）。`finish()` 与 `abort()` 都把 procedure 从 world 的战斗槽位交还（槽位仍指着它才清；`world.tick()` 收尾与 `end()` 中止之后 world 侧断言槽位已交还再兜底清空——经 `world.tick()` 收尾时子类 `finish()` 漏调 super 会响亮报错，调用方直接 `finish()` 的路径不经过这道断言）；`world.tick()` 发现槽位在这次 `tick_once()` 里被交还（world 被结束，或 procedure 自己调了 `finish()`）时不再推进、不收尾、不发信号——那次 `tick_once()` 余下的函数体照样跑完，procedure 判定结束应 `mark_finished()`。abort 写在 `end()` 而不是 `on_end()`：后者是留给子类的空钩子，覆盖时漏调 super 就会把泄漏接回来。why：录像的订阅闭包与被录 actor 互相强持，此前只有 `finish()` 与项目 GI 的 `get_replay_data()` 会一次退订全部——开着录像的战斗中途 `destroy_instance` / `shutdown()` / `destroy_all_instances()`（如 inkmon `smoke_world_command` 的 `request_training_battle` → `tick_once` → `destroy_all_instances`）把 recorder 与它订阅的全部 actor（含不参战的常驻者与中途 spawn）留到进程退出；槽位此前只在 `world.tick()` 收尾时置空，dota2 这类直接驱动 `finish()` 的流程之后 `has_active_battle()` 仍为真，同一 world 再 `start_battle` 会撞断言。回归：释放测试用例 3（procedure 子类被直接 `finish()` 后槽位已交还）、用例 4（覆盖 `on_end` 不调 super 的 world 子类，录像战斗的 tick 里 `GameWorld.shutdown()`：tick 期间零错误、不收尾不发信号、录像已停、订阅表清空、recorder 与全部被录 actor 释放），用例 2–4 另断言 world 结束后仍持有 procedure 时放掉 world 局部引用、world 当场释放。
- **world ↔ procedure 强引用环（hex `HexBattleProcedure` / dota2 `Dota2AutoBattleProcedure`；主仓 inkmon `InkMonBattleProcedure` 同步）**：子类删掉 `_world_instance` 字段，改为协变覆盖 `_get_world() -> 具体世界类型`（读基类 `_world` WeakRef，没有可写回的存储槽）。why：`WorldGameplayInstance._active_battle` 强持 procedure，procedure 再强持 world 就成环，而 `_active_battle` 只在 `world.tick()` 收尾时置空——直接驱动 procedure 结束（dota2 smoke 与前端，`_restart()` 每重开一局漏一整场）或战斗中途 destroy 时，world、procedure 与全部 actor / AbilitySet / Ability / execution 一起留到进程退出（dota2 泄漏直方图里残留的 RefCounted / WeakRef 即此）。修复后 Changed「typed instance」里「引用图不成环」的证明对 procedure 子类同样成立；开着录像的战斗中途 destroy 仍会经 recorder 订阅闭包留下 recorder 与它订阅的全部 actor（开战时 `get_recordable_actors()` 全体加战斗中补录的 spawn，不止参战者）——`end()` / `destroy_instance` 不停录像，一次退订全部的 `stop_recording` 只由 `finish()` 与项目 GI 的 `get_replay_data()` 调用——不在本条范围（随后由同段 Fixed「world 结束时进行中的战斗泄漏 recorder…」修复）。
- **测试 runner load 失败 fail-open**：`tests/run_tests.gd` 原先对 `load()` 返回 null 的测试脚本仅 `push_error` + continue，退出码只统计断言失败——一个 parse error 会让套件静默缩水成"全绿"。现在 load null / `can_instantiate()` false / `new()` 非 Node 三类都记入 load_failures 并打印 `TEST LOAD FAILURE:` 行，`quit(failures + load_failures)`。why：退出码是 CI/门禁的唯一真值，加载失败必须与断言失败同权重判死。
- **同 timestamp 的多个 timeline tag 缺显式二级排序**：`AbilityExecutionInstance` 的 tag 触发与 `TimelineData.get_sorted_tags()` 补齐定义序（tags 声明顺序）tie-break，同刻 tag 按 (tag_time, 定义序) 全序执行。why：`Array.sort_custom` 不稳定，缺 tie-break 时同刻 tag 的执行序取决于排序算法内部实现与容器遍历序——同一份 timeline 在不同运行里可能给出不同的 Action 执行序，破坏 replay 确定性；定义序让作者声明顺序即执行顺序。回归：`ability_execution_instance_test.gd`（tick 同刻四 tag 定义序触发）、`timeline_test.gd`（get_sorted_tags tie-break）。
- **loop timeline 跨周期时超出周期的时间余量被丢弃**：本轮溢出 `total_duration` 的余量现结转为下一轮的起始 `_elapsed`，且结转窗口 `(0, carry]` 内的 tag 在同一次 tick 补触发（不补扫会被下一次 tick 的窗口起点跳过）；max_loops 达成的终轮维持原语义不结转。why：余量清零把每个实际周期拉长到 tick 边界，周期节奏随调用方 dt 漂移（如 100ms 周期在 dt=60 下变 120ms，300ms 只跑 2 轮而非 3 轮），DOT/HOT 的 tick 总数与配置周期脱钩且不可跨 dt 复现；dt 恰为周期整倍数时（现有 example 均如此）行为逐位不变。回归：`timeline_loop_test.gd`（余量结转+补触发、节奏不漂移、终轮不结转）。
- **`ProjectileHit` 的 kind 常量归 core 注册表**：`GameEvent` 新增 `PROJECTILE_HIT_EVENT` 常量，`ProjectileHit` 改用之；stdlib `ProjectileEvents.PROJECTILE_HIT_EVENT` 转引 core 常量（值不变 `"projectileHit"`，行为逐位等价）——消除投射物工厂迁 stdlib 后 `game_event.gd` 对其残留的 core→stdlib 反向引用（codex review P2）。

## [Baseline] — 2026-05-31

文档 baseline 重置。此前逐阶段变更记录（Phase A–G、多轮 `[Unreleased]` 子段、各 design-note 长文）已归档为快照——完整轨迹见 git 历史。以下为当前框架与示例的能力快照，作为后续变更的基线。

### 框架核心 (`core/`)

- **Entity**：`Actor` / `System` + `GameWorld`（autoload 单例，`get_actor()` 统一查询入口，ID 格式 `{instance_id}:{local_id}`）。
- **World owns Battle**：`WorldGameplayInstance` 持有 actor registry / grid / systems，战斗降级为短命 `BattleProcedure`；前端响应式观察 world（见 `docs/README.md` 的 "World owns Battle + 响应式前端" 节）。
- **Ability**：`Ability` / `AbilitySet` + Timeline keyframe 驱动；Action 四层分层（Util / Primitive / Flow / SkillLocal，契约见 `docs/reference/action-architecture.md`），由轻量 validator 守边界。
- **Attribute**：`RawAttributeSet` + 4 层公式计算 + config 驱动跨属性 clamp（`maxRef` / `minRef` → `register_cross_attr_clamp`）。
- **Event**：`EventProcessor` pre/post + Intent（PASS / MODIFY / CANCEL）+ 强类型事件类；`EventCollector` 单 buffer，录像顺序 = 调用栈真实顺序。
- **Tag**：loose / auto-duration / component 三来源（语义见 action-architecture.md）。
- 结构性循环已根治：子对象回指 container 一律 `WeakRef` 或调用链参数流，无字段缓存 owner。

### 标准库 (`stdlib/`)

- Components：`StatModifierComponent` / `DurationComponent` 等。
- Systems：`ProjectileSystem`。
- Replay：`BattleRecorder`（A 层 "录像播放" Playback 现役；B 层确定性 Replay 仅命名占位）。录像格式 `PROTOCOL_VERSION` = v2。

### 示例 (`example/`)

- **hex-atb-battle**：回合制 + hex grid 战斗示例；~30 个 active ability + buff/passive 体系、skill-preview 沙盒、前端 `FrontendWorldView` / `FrontendBattleAnimator` 响应式表演层。专属文档见 `example/hex-atb-battle/README.md`。
- **dota2-auto-battle**：自动战斗示例（controller-intent + tick model）。专属文档见 `example/dota2-auto-battle/README.md`。
- **assets/tiny_swords**：共享美术资产包 + `TinySwordsCatalog` / `TinySwordsAnimationCatalog` 加载器。

> 已知债务与未来规划见 `docs/README.md` 的 "未来规划 / 已知债务" 节。
